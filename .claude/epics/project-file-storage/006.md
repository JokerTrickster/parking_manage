# File Storage System - User Guide

## Overview
The file storage system allows you to manage project files including map configurations, CAD drawings, ROI settings, and training/test images.

## Accessing File Storage
1. Log into the parking management system
2. Navigate to [File Storage page location]
3. Select your project (e.g., banpo, osong)

## File Categories

### Map JSON Files
- **Purpose**: Store parking map configurations
- **Versioning**: Automatic - each upload creates a new version
- **Usage**:
  1. Click "Map JSON" tab
  2. Click "Choose File" button
  3. Select your map JSON file
  4. File uploads automatically with version number

**Version History**:
- View all previous versions in the list
- Click download icon to download specific version
- Latest version is displayed at the top

### CAD Files
- **Purpose**: Store architectural drawings and site layouts
- **Supported Formats**: .dwg, .dxf, and other CAD formats
- **Versioning**: Automatic
- **Usage**: Same as Map JSON

### ROI JSON Files
- **Purpose**: Store region of interest configurations
- **Versioning**: Automatic
- **Usage**: Same as Map JSON

### Learning Images
- **Purpose**: Store training images for parking detection algorithm
- **Organization**: Organized by CCTV ID (e.g., P1_B2_1_2)
- **Versioning**: No versioning (folder-based)
- **Usage**:
  1. Click "Learning Images" tab
  2. Click "Choose Folder" button
  3. Select folder containing CCTV ID subfolders
  4. Wait for upload to complete (progress bar shows status)

**Folder Structure Example**:
```
learning_images/
├── P1_B2_1_2/
│   ├── image001.jpg
│   └── image002.jpg
└── P1_B2_1_3/
    └── image001.jpg
```

### Test Images
- **Purpose**: Store test images for validation
- **Organization**: Same as Learning Images
- **Usage**: Same as Learning Images

## Downloading Files
1. Navigate to desired category tab
2. Locate file in file browser
3. Click download icon next to filename
4. File downloads to your browser's download folder

- Upload files regularly to maintain backups

- Check internet connection

- Try smaller batch if uploading many files

### File Not Appearing
- Refresh page
- Check correct category tab
- Verify project ID is correct

### Download Not Working
- Check browser allows downloads
- Verify file still exists on server
- Try different browser

# Map Editor Integration Guide

## Overview
This guide explains how to integrate the file storage auto-upload feature into the map editor.

## Auto-Upload Endpoint

**Endpoint**: `POST /api/filestorage/{projectId}/map/auto-upload`

**Purpose**: Automatically upload map JSON when user exports from map editor

**Behavior**:
- Asynchronous (fire-and-forget)
- Returns immediately (202 Accepted)
- Upload happens in background
- Errors logged server-side, not shown to user

## Integration Steps

### 1. Modify Export Function

Add auto-upload call to your export function:

```typescript
async function exportMap(projectId: string, mapData: any) {
  // Generate JSON
  const jsonString = JSON.stringify(mapData, null, 2);
  const jsonBlob = new Blob([jsonString], { type: 'application/json' });

  // Trigger auto-upload (don't await)
  autoUploadMap(projectId, jsonBlob);

  // Continue with normal export (download to user)
  downloadJsonToUser(jsonBlob, 'parking_map.json');
}

async function autoUploadMap(projectId: string, jsonBlob: Blob) {
  const formData = new FormData();
  formData.append('file', jsonBlob, 'parking_map.json');

  try {
    const response = await fetch(
      `/api/filestorage/${projectId}/map/auto-upload`,
      {
        method: 'POST',
        body: formData,
      }
    );

    if (response.ok) {
      console.log('Map auto-uploaded successfully');
    }
  } catch (error) {
    // Silently log error - don't show to user
    console.warn('Auto-upload failed:', error);
  }
}
```

### 2. Test Integration

**Test Checklist**:
- [ ] Export map → verify auto-upload called
- [ ] Export completes without delay
- [ ] Verify file appears in file storage system
- [ ] Test with large map (>10MB)
- [ ] Simulate network failure → verify export still works

### 3. Error Handling

**Important**: Auto-upload should NEVER block or interrupt the export process.

```typescript
// ✅ CORRECT: Fire-and-forget
autoUploadMap(projectId, jsonBlob); // Don't await
downloadJsonToUser(jsonBlob);

// ❌ WRONG: Awaiting blocks export
await autoUploadMap(projectId, jsonBlob);
downloadJsonToUser(jsonBlob);
```

## API Response

**Success Response** (202 Accepted):
```json
{
  "success": true,
  "message": "Upload initiated",
  "data": {
    "project_id": "banpo",
    "filename": "parking_map.json"
  }
}
```

**Note**: 202 status means upload initiated, not completed.

## Server Logs

Auto-upload operations are logged:

```
[AUTO-UPLOAD] SUCCESS: project=banpo, file=parking_map.json, version=1698765432
[AUTO-UPLOAD] ERROR: project=osong, file=parking_map.json, error=disk full
```

Monitor logs to verify auto-upload working correctly.

## Fallback

If auto-upload fails, users can manually upload via the File Storage UI:
1. Navigate to File Storage page
2. Click "Map JSON" tab
3. Upload file manually

## Support

For integration issues, contact: [backend team contact]
